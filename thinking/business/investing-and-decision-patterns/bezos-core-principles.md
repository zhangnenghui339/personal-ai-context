## 一句话

**Bezos 把失败设计成有限损失，把成功设计成无限收益，再让失败过程本身沉淀资产；发现结构性势差后趁巨头没转身抢占市场，把套利赚的钱修成关不掉的基础设施，用飞轮把一次性领先变成终值。** 失败时像 VC，成功后像垄断型基础设施公司。

## 一、决策心法（两领域通用）

| 模型 | 出处 | 内容 |
|---|---|---|
| 后悔最小化框架 | 1994 离职决定 | 面对不可逆的复利型赌注，先问「80 岁回头看会不会后悔」，不是先问期望值。 |
| 单向门 / 双向门 | 2015 信 | 可逆决策（双向门）快速做、低层级做；不可逆决策（单向门）才慢慎。多数决策是双向门却被当单向门处理。 |
| Math-based vs judgment-based | 2005 信 | 能算的决策用算的（共识度高）；要判断的充分辩论，一旦做出停止辩论。 |
| Disagree and commit | 2016 信 | 有信念但无共识时，让对方「不同意但执行」，换组织决策速度。 |
| Day 1 / Day 2 | 2016 信 | Day 2 是停滞→无关→痛苦衰退→死亡。护城河是动态的，每天重新守。 |

## 二、投资 / 资本配置领域（幂律数学）

- **10% × 100x（2015 信）：**「给你 10% 的概率赢 100 倍，你每次都该下这个注。」10 个实验各最多亏 1：9 亏 −9、1 中 +100，组合 +91。**单项目成功率低 ≠ 系统决策质量低。**
- **逆共识（2015 信）：**「outsized returns 往往来自跟主流判断对着干，而主流判断通常是对的。」不矛盾——这是幂律 / 偏态分布下的**组合逻辑**，不是单笔逻辑：多数逆共识赌注会输（共识大概率对），但超额回报只能来自少数「逆共识且押对」。和 10%/100x 是同一个数学结构。
- **打击率 vs 长打率：** 棒球截断右尾（本垒打最多 4 分），商业不截断（一次挥棒能得 1000 分）。看 slugging（长打率），不看 batting average（打击率）。追高胜率会把你推向安全、共识、上行封顶的项目。
- **规模扩大，实验也要扩大（2018 信）：** 公司大了，失败实验的规模也该同步变大；几次十亿美元级失败没关系，只要偶尔换来一个 AWS。
- **两个前提，绝不是「随便烧钱」：**
  - ① Downside 可控：`Max Loss << Survival Capital`，单次失败不能杀死母公司或永久破坏核心品牌 / 现金流 / 资产负债表。
  - ② Upside 足够大：Downside=100 / Upside=120 即使高概率也不算幂律下注；要的是 Downside=1 / Upside=100–1000。
- **加残值的期望值：** `Adjusted EV = P(success)×Upside − P(failure)×(Downside − Residual Asset Value)`。偏好能沉淀 code / infra / data / talent / distribution / customer relationship / seller network / brand 的实验。
- **失败资产化（Failure Assetization）：** 传统失败模型「投入→失败→归零」；Bezos 的「投入→失败→人才 / 技术 / 数据 / 基础设施 / 认知残值→下一轮实验边际成本下降」。`Net Loss = 投入 − 项目收入 − 可复用资产残值`。推论：让失败发生在**可复用能力附近**（Fire Phone 失败，语音 / ML / 硬件团队迁到 Echo / Alexa）。
- **「烧钱换规模」是否理性的判据：** 不看烧了多少，看补贴退潮后钱变成的东西能不能被别人零成本抢走。= `thinking/business/potential-energy-and-gaps/hobart-arbitrage-infrastructure.md` 的 Arbs close, infrastructure remains。

## 三、商业领域（运营一家公司）

- **窗口期（1997 信）：** 基础设施相变打开一个短暂窗口，窗口关闭来自巨头完成组织动员——不受你意志控制。窗口内要 move fast to solidify and extend position。
- **市场领导地位 → 收益递增：** 领先直接转化为更高收入、利润率、资本周转和回报。底层是三种收益递增条件叠加：网络效应 + 经验曲线（Wright's Law）+ 可内部化的固定资产。领导地位不是目标，是「进入自我强化结构」的中间状态。
- **最大化未来现金流现值，不优化 GAAP 账面（1997 / 2004 信）：** 股票只值未来现金流的现值，不是盈利的现值。翻译成 DCF：牺牲显性预测期现金流，去换**终值**——延长竞争优势期（CAP）、加宽 ROIC − WACC 价差。
- **飞轮（2001）：** 低价→更多顾客→更多第三方卖家→更大选品→更好体验→更多顾客；规模摊薄固定成本→反哺更低价。一次性领先靠飞轮变成自我强化结构。
- **客户至上当罗盘：** 把「跟竞争对手比」从决策变量里剔除。
- **基础设施抽取（Infrastructure Extraction）：** Amazon 的母能力不是电商，是不断发现内部已规模化解决、又是全市场公共问题的能力，把它标准化→API 化→开放第三方→变成独立营收引擎（Marketplace、FBA、Prime、AWS、Ads）。
- **Explore / Exploit 两阶段：** 探索期——双向门、小仓位、高失败率，目标是 information gain 不是利润；利用期——强信号出现→大幅加码、抢市场领导地位、建难复制的基础设施。
- **招聘门槛：**「你会敬佩这个人吗？他会拉高团队平均效能吗？」用「边际是否提升」当门槛。Two-pizza teams 降沟通复杂度。

## 四、方法论：怎么找到最初那个机会（细化）

> 可操作漏斗版见 `thinking/business/investing-and-decision-patterns/bezos-wedge-selection-funnel.md`（Layer 0 认相变 → Layer 1 成本结构倒推品类 → Layer 2 wedge 结构条件 → Layer 3 当期权 → Layer 4 幂律 / 窗口 / 可占有性三道闸）。

**前提认知：** 商业模式成熟之前，机会信号只存在于渠道 / 基础设施层。等 GMV / 销售数据出来，窗口已经在关闭（巨头已完成组织动员）。幂律的另一面：一个基础设施级相变会**同时重塑多个行业**，所以正确顺序是先抓相变，再选战场，而不是先有品类偏好。

### Step 1：识别基础设施级相变，用先行指标而非销售数据

**什么算「基础设施级」：** 不是某个产品变好，是**分发 / 交易 / 计算的底层成本结构**变了。

信号的四个特征：

- 出现在商业模式成熟之前（1994 年电商销售额几乎不存在）
- 位于渠道 / 基础设施层，不是应用层
- 增长是**数量级**的，不是百分比（Web 使用量 ~2,300%/年）
- 一旦成立会横向外溢，同时重塑多个行业

Bezos 当时在 D.E. Shaw 的工作就是「互联网商业机会研究」，他把渠道渗透率曲线当未来市场规模的代理变量，而不是等某个垂类的销售额跑出来。

**两个陷阱：** 把某个热门**产品**当相变（那是应用层噪声）；把一时的线性增长当指数增长。区分结构性迁移与噪声见 `thinking/business/potential-energy-and-gaps/structural-migration-vs-noise.md`。

### Step 2：给定新渠道的成本结构，倒推哪个存量品类最适合被重塑

提问方式的转换：不是「我想卖什么 / 我喜欢什么」，而是「新成本结构对哪个存量品类的**改造幅度**最大」。

互联网相对实体零售改变的成本项：物理货架成本（有限→近乎无限 SKU）、选品 / 库存成本、地理触达成本、信息成本（搜索 / 比价）。

候选品类的筛选维度（要多个同时成立）：

| 维度 | 图书为什么成立 |
|---|---|
| 供给端集中、容易接入 | 美国图书批发高度集中（Ingram、Baker & Taylor），一次接入拿到几乎全部书目 |
| 产品标准化、可搜索 | ISBN 全球唯一编码，天然结构化数据，无需人工整理商品库 |
| 信任 / 试用成本低 | 书不用试穿试用，同一本书在哪买都一样，退货率低 |
| 现有物理渠道有真实货架瓶颈 | 最大实体书店约 10 万 SKU，在版图书 150 万+，线上能提供 10 倍以上 Selection |
| 线上扩 Selection 对用户有价值 | 长尾书需求真实存在，实体店满足不了 |
| 客单价 / 复购能覆盖履约成本 | 单价适中、复购频次可观 |

图书是少数几个上述维度**全中**的品类。

### Step 3：横向候选集打分，不是单点直觉

Bezos 据传列了约 20 个品类（书、音乐 CD、软件、办公用品、服装、五金……），用统一维度打分：

- 音乐 CD：标准化高，但供给端被几大唱片公司卡授权、单价偏低
- 服装：非标、要试穿、退货率高 → 淘汰

关键是**先建候选集、再用同一套维度筛选**。「灵光一现选了书」是结果叙事，不是方法。

### Step 4：把「选中的品类」当期权，不是当终点

图书是 **wedge（切入口）不是商业本质**。它的结构优势会随横向扩品类下降——百货 SKU 复杂度、库存风险陡增，物流成为竞争核心（当当的教训：复制了产品序列「书→百货→marketplace」，没复制产生这个序列的底层能力）。

所以进入 wedge 时就要想清楚：它帮我积累什么**可迁移能力**（用户、履约网络、数据、品牌信任）。选品类是买一个进入自我强化结构的期权，不是终局。

### 2026 年的等价观测点

| 类别 | 1994 年 Bezos 用的信号 | 2026 年等价观测点 |
|---|---|---|
| 渠道渗透率 | Web 使用量增长 | 官方互联网 / 移动统计、AI 使用渗透率、Agent 调用量 |
| 应用层采纳曲线 | 当时无成熟对应 | App Store / Google Play 下载增长、Similarweb、Sensor Tower |
| 注意力迁移 | 当时无成熟对应 | Google Trends、GEO 引用流量、AI 对话流量 vs Search |
| 供给侧资本信号 | 当时无成熟对应 | VC 融资笔数 / 金额环比、巨头 CapEx 落点 |
| 开发者生态 | 当时无成熟对应 | GitHub star、npm / pip 下载、API 调用增长 |
| 需求侧信号 | 当时无成熟对应 | LinkedIn / 招聘职位按技能、岗位增长 |

### 两个诚实提醒

1. 1994 年的信号极稀缺且极大；2026 年信号更碎片化、噪声更大 → 更多机会来自**垂直领域的小规模相变**。
2. 竞争优势越来越依赖**观测点本身的专有性**——一手抓取数据、独有工作流、内部行为数据，而不是人人都能看到的公开报告。
